# اتصال حساب کاربری تلگرام — نسخه ۱.۹.۴

App api_id و App api_hash با توکن ربات تفاوت دارند. برای دریافت مستقیم تاریخچه کانال تحت مدیریت خود، روش «حساب کاربری» اضافه شده است. هیچ مقدار واقعی، کلید، شماره تلفن یا نشست حسابی در فایل توزیع‌شده وجود ندارد.

## نصب و ورود روی کامپیوتر خودتان

در پوشه سایت و با Python 3.11 یا جدیدتر:

```cmd
python -m pip install -r requirements-account.txt
python server.py
```

اگر نصب تازه است، پیش از اجرای سایت یک بار `python server.py init-admin` را اجرا کنید. در نصب قبلی پوشه data را نگه دارید.

در پنل محلی `/admin` تب «دستیار تلگرام»:

1. روش دریافت را «حساب کاربری (تاریخچه و پست‌های جدید)» انتخاب کنید.
2. App API ID و API hash خود را در فیلدهای مخصوص ذخیره کنید. این‌ها از my.telegram.org دریافت می‌شوند و جای کلید OpenAI را نمی‌گیرند.
3. شناسه عمومی، شناسه عددی یا لینک دعوت خصوصی کانال خود را تنظیم کنید. روش تحلیل را Ollama محلی یا OpenAI انتخاب کنید؛ فقط OpenAI به کلید و اعتبار API نیاز دارد. برای لینک خصوصی، حساب تلگرام باید از قبل عضو و مدیر همان کانال باشد. ورود به حساب را می‌توانید قبل از فعال کردن دستیار انجام دهید.

یک ترمینال دیگر در همان پوشه باز کنید:

```cmd
python telegram_account.py login
```

شماره تلفن با کد کشور، کد ورود تلگرام و در صورت فعال‌بودن، رمز دومرحله‌ای را **فقط در ترمینال دستگاه خودتان** وارد کنید؛ در چت، سایت عمومی یا GitHub نفرستید. پس از ورود موفق، نشست در data/telegram-account.session باقی می‌ماند و معمولاً ورود دوباره لازم نیست.

در پنل تیک انتشار خودکار را فعال کنید و در ترمینال دوم اجرا کنید:

```cmd
python telegram_account.py watch
```

سرور سایت و دریافت‌کننده حساب هر دو باید در حال اجرا باشند. این روش برای دریافت پست به ربات نیاز ندارد. دریافت‌کننده فقط کانال انتخاب‌شده را می‌خواند و مدیریت یا مالکیت شما را بررسی می‌کند. پیام ارسال نمی‌کند و کانال جدیدی را خودکار دنبال نمی‌کند. عکس و متن به روش تحلیل انتخاب‌شده فرستاده می‌شوند. ویدیوهای تا ۱۰۰ MiB به‌طور موقت دریافت و حداکثر سه فریم از آن‌ها استخراج می‌شود؛ فایل موقت بعد از استخراج پاک می‌شود و فایل کامل ویدیو به مدل فرستاده نمی‌شود. در صورت شکست دانلود یا استخراج، پیش‌نمایش موجود تلگرام امتحان می‌شود.

## خطای GetFileRequest و صف دریافت رسانه

دانلود عکس/پیش‌نمایش مهلت ۳۰ ثانیه و دانلود ویدیو مهلت ۹۰ ثانیه دارد؛ استخراج هر فریم حداکثر ۱۵ ثانیه صبر می‌کند و فرایند متوقف‌شده پاک‌سازی می‌شود. اگر هیچ تصویر قابل‌استفاده‌ای از پست تصویری/ویدیویی نرسد، پست در وضعیت `waiting_media` ذخیره و دریافت پست‌های بعدی ادامه داده می‌شود. در این مرحله مدل آن پست را تحلیل نمی‌کند. اطلاعات فایل در تلاش بعدی از تلگرام تازه می‌شود؛ صف حتی برای پست‌های قدیمی‌تر از پنجرهٔ ۵۰ پیام اخیر، پس از راه‌اندازی مجدد باقی می‌ماند.

چهار تلاش خودکار بعدی با فاصله‌های ۱، ۲، ۴ و ۸ دقیقه زمان‌بندی می‌شوند. بعد از پنجمین شکست، وضعیت `media_failed` نیازمند دکمهٔ «تلاش دوباره موارد ناموفق» در پنل است. دریافت‌کنندهٔ `watch` باید برای این کار روشن بماند. اگر فایل با تصویر بندانگشتی جایگزین شده باشد، ورودی مدل فقط همان پیش‌نمایش و کپشن است و این محدودیت به مدل گفته می‌شود.

پست‌های منتشرشده هنگام انتظار برای رسانهٔ ویرایش‌شده همچنان نمایش داده می‌شوند. وضعیت دریافت‌کننده و شمارهٔ پست در پنل هر ۵ ثانیه تازه می‌شود. دانلود موفقِ بدون تغییر دوباره انجام نمی‌شود؛ شکست دانلود نیز به‌عنوان موفقیت در حافظه باقی نمی‌ماند. هنگام `FloodWait` کل دریافت‌کننده به اندازهٔ زمان تعیین‌شده توسط تلگرام منتظر می‌ماند.

## تاریخچه

بار اول ۲۰۰ پیام آخرِ قابل دسترس صف می‌شوند. برای دریافت تمام تاریخچه قابل دسترس از همان شروع اول:

```cmd
python telegram_account.py watch --history-limit 0
```

این گزینه ممکن است تعداد زیادی درخواست OpenAI و هزینه ایجاد کند. پس از ثبت نقطه ادامه، اجراهای بعدی از همان نقطه تمام پیام‌های جامانده را دریافت می‌کنند. تغییر history-limit نقطه ادامه قبلی را به عقب برنمی‌گرداند. برای آرشیو قدیمی‌تر از نقطه شروع می‌توانید همچنان از ورود JSON توضیح‌داده‌شده در ASSISTANT_FA.md استفاده کنید.

اگر نسخهٔ قبلی پست‌های ویدیویی بدون کپشن را رد کرده است، یک بار پنجرهٔ موردنیاز را دوباره بررسی کنید:

```cmd
python telegram_account.py watch --rescan-limit 500
```

عدد ۵۰۰ نمونه است. هر پست این پنجره فقط در صورت تغییر متن/رسانه دوباره صف می‌شود و نقطهٔ ادامه عقب نمی‌رود. بازخوانی بزرگ‌تر می‌تواند مصرف Telegram و OpenAI را افزایش دهد.

پست‌های جدید معمولاً هر ۱۵ ثانیه بررسی می‌شوند. ویرایش‌ها هنگام اتصال با رویداد تلگرام دریافت و ۵۰ پیام اخیر هم پس از اتصال مجدد بازبینی می‌شوند. ویرایش پیام‌های بسیار قدیمی در زمان قطع ارتباط و حذف پست‌ها تضمین همگام‌سازی ندارند. کپشن، نوع رسانه، مدت و نام فایل در دسترس تحلیل می‌شوند. برای عکس و ویدیو، تصویر یا تصویر بندانگشتی نیز ارسال می‌شود؛ بنابراین پست تصویری یا ویدیویی بدون کپشن دیگر از صف حذف نمی‌شود. تحلیل کل صدا یا تمام فریم‌های ویدیو انجام نمی‌شود.

برداشتن تیک فعال‌سازی، دریافت‌کننده را متوقف می‌کند؛ پس از فعال‌سازی دوباره فرمان watch را اجرا کنید. درخواست/پردازش در حال اجرا ممکن است کامل شود. دریافت‌کننده را هم‌زمان در دو ترمینال با یک فایل session اجرا نکنید. اگر سهمیه Telegram محدود شود، برنامه مطابق زمان FloodWait صبر می‌کند.

## اطلاعات خصوصی

پوشه data شامل کلیدها و نشست واردشده است و باید خصوصی بماند. فایل session امکان دسترسی به حساب می‌دهد؛ آن را در GitHub یا فایل ZIP عمومی نگذارید. روی Linux فایل‌های نشست با دسترسی محدود ساخته می‌شوند؛ در Windows دسترسی پوشه را به حساب خود محدود کنید. برای لغو دسترسی نشست، در Telegram بخش Settings > Devices همان نشست را خاتمه دهید.

اتصال حساب از MTProto استفاده می‌کند و به دسترسی مستقیم شبکه به سرورهای Telegram نیاز دارد. محیط‌های صرفاً HTTP-proxy ممکن است آن را پشتیبانی نکنند. اجرا و ورود واقعی باید روی دستگاه خودتان انجام شود. این نسخه بدون ورود به حساب واقعی و بدون مصرف API واقعی OpenAI آزمایش شده است؛ آزمون خودکار، دریافت/صف/ادامه پردازش را با داده شبیه‌سازی‌شده می‌سنجد.
